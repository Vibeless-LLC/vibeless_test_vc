# Gridline decisions

Decision log for Gridline (.NET 10 Windows spreadsheet engine plus CLI). Each entry cites the spec section it implements.

## Phase 1

### D-1 Solution layout (§3.1)
`Gridline.sln` at the root with the four src projects `src/Gridline.{Core,IO,Cli,App}` and the five test projects `tests/Gridline.{Core,IO,Cli,App,Architecture}.Tests` (§3.1); no other projects. Phases 1-2 had the first three src and four test projects; App and App.Tests were added in Phase 3 Task 6 (D-37).

### D-2 Project references (§3.2)
Core references nothing. IO references Core. Cli references Core and IO. Each test project references the src projects it tests; Architecture.Tests references all src projects (App since D-37). App references Core and IO.

### D-3 Build settings (§2)
Shared settings live in the root `Directory.Build.props`: `net10.0`, `LangVersion latest`, `Nullable enable`, `WarningsAsErrors=Nullable` (only nullable warnings are errors), ImplicitUsings enabled. Cli sets `OutputType Exe`, `AssemblyName gridline`, `RootNamespace Gridline.Cli`.

### D-4 Packages (§2)
No packages in `src/`. Test projects take only what they need from the §2 list, with pinned stable versions: xunit 2.9.3, xunit.runner.visualstudio 3.1.4, Microsoft.NET.Test.Sdk 17.14.1, coverlet.collector 6.0.4; Architecture.Tests also NetArchTest.Rules 1.3.2. FsCheck.Xunit 3.5.0 is used by Gridline.IO.Tests (round-trip property tests) and Gridline.Core.Tests (printer property, D-33). FlaUI.UIA3 5.0.0 is used by Gridline.App.Tests (D-37).

### D-5 Core namespace folders (§3.3)
Core has Addressing, Parsing, Evaluation, Functions, Dependencies and Commands folders, each held by a `.gitkeep` until populated; all are populated now (`Commands` since Phase 3 Task 3, D-34).

### D-6 Addressing grammar and bounds (§4.2, §4.3)
`Gridline.Core.Addressing` holds `GridBounds` (public consts MaxColumns 702 = A..ZZ, MaxRows 100000), `ColumnName` (letters<->number), `CellAddress` (validated, canonical uppercase no-$ `ToString`), `CellReference` (keeps `$` flags for formulas) and `CellRange` (normalised top-left:bottom-right, so `B3:A1` becomes `A1:B3`). It depends on no other Core namespace. `TryParse` reports failure; `Parse` throws `ArgumentException`; constructors throw `ArgumentOutOfRangeException` for out-of-bounds values. Parsing is case-insensitive, ASCII only, and rejects any whitespace, null, empty, a lone `$`, `A0`, `AAA1`, rows over 100000.
Choice: a row with a leading zero such as `A01` is rejected (keeps one canonical spelling). `CellAddress.TryParse` and `CellRange.TryParse` accept `$` markers and discard them; use `CellReference` when the flags matter.

### D-7 Value kinds and error codes (§9.1)
`Gridline.Core.ValueKind` = Blank, Number, Text, Boolean, Error. `ErrorCodes` is a static class of public consts, exactly as §9.1 lists them: Div0 `#DIV/0!`, Value `#VALUE!`, Ref `#REF!`, Name `#NAME?`, NA `#N/A`, Num `#NUM!`, Circ `#CIRC!`, Parse `#PARSE!` (§4.5). Phase 3 Task 1 renamed the former `DivZero` to `Div0` everywhere, with no alias (spec 1.0 supersedes the R2 constant name; the code set R2 chose is confirmed). Membership is tested with `ErrorCodes.IsKnown`, backed by a private FrozenSet (no public mutable static state, §3.3).

### D-8 CellValue (§9.1, §8.3)
`CellValue` is a readonly struct; `default` and `CellValue.Blank` are the blank value. `FromNumber` normalises -0 to 0 and turns NaN/infinity into the `#NUM!` error, so equality and hash codes stay consistent. `FromText(null)` throws ArgumentNullException; `FromError` throws ArgumentException for a code not in `ErrorCodes`. §9.1 (Phase 3 Task 1, replacing the earlier throw-on-wrong-kind choice): each payload accessor returns its default on the wrong kind and never throws: `Number` is 0 unless Kind is Number, `Text` is "" unless Text, `Boolean` is false unless Boolean, `Error` is "" unless Error (`default(CellValue)` included). Callers that need to tell a real 0/""/FALSE from a default test `Kind` first; every engine caller already did. Equality compares Kind and payload: text and errors ordinally, numbers with `==`. Text longer than 32,767 code units is the caller's concern, not CellValue's.

### D-9 Canonical value strings (§8.3)
`ToCanonicalString`: Blank `BLANK`; Number `N:` + `ToString("R", InvariantCulture)` (-0 prints `N:0` via normalisation); Text `T:` + text with only backslash, TAB, LF and CR escaped (as `\\`, `\t`, `\n`, `\r`); Boolean `B:TRUE`/`B:FALSE`; Error `E:` + code. `ToString()` returns the same form.

### D-10 Cell input interpretation (§4.3)
`CellInputInterpreter.Interpret` (root namespace `Gridline.Core`, no Parsing/Evaluation dependency) applies the rules in order, first match wins: empty -> Blank; leading `=` -> Formula (`FormulaText` is the rest; a lone `=` is a Formula with empty text, which the parser later turns into `#PARSE!`); leading `'` -> Text minus that one apostrophe; case-insensitive whole-string TRUE/FALSE -> Boolean (no trimming, so `TRUE ` is text); number grammar -> Number; otherwise verbatim Text (no trimming, so ` 5` is text). Result is `CellInputResult(Kind, Value, FormulaText)`.
Choice: a lone `'` yields Text `""` (not Blank), so the cell stays a text cell. `MaxInputLength = 32767` UTF-16 units lives on `CellInputInterpreter`; longer input throws ArgumentException, null throws ArgumentNullException.

### D-11 Number grammar (§4.3, §6.2)
`NumberGrammar.TryParse(ReadOnlySpan<char>, out double)` is a hand-written span matcher for `^[+-]?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?%?$`, no allocation or regex. Choice: `\d` means ASCII 0-9 only (non-ASCII digits are text), since the engine is culture-invariant. Value parsed with `double.TryParse(NumberStyles.Float, InvariantCulture)`, trailing `%` divides by 100, -0 normalised to 0, and a non-finite result (`1e999`) is not a number so the input becomes Text. Only one `%` is allowed (`5%%` is text). No trimming here; §6.2 coercion callers trim U+0020 first.

### D-12 Formula tokenizer (§5.1)
`Gridline.Core.Parsing.Tokenizer.Tokenize(formulaText)` (input is the text after the leading `=`) is one linear pass, no recursion, no Regex. It returns a `TokenizeResult` (tokens ending in `End`, or `ErrorMessage` + 0-based `ErrorPosition`); user-input errors never throw (a failed tokenize becomes a `#PARSE!` formula later). `Token` is a readonly record struct: Kind, Position, Lexeme (exact source text, needed for §5.5), plus payload (Number, Text, Boolean, Reference). Depends only on Addressing and root Core types.
R6 (numbers): literal forms are `digits ['.' digits*] [exponent]` and `'.' digits [exponent]`, exponent `[eE][+-]?digits`; no sign and no `%` (those are Minus/Plus and Percent tokens). Value is `double.Parse(lexeme, NumberStyles.Float, InvariantCulture)`; R53 (§4.4, Phase 3 Task 1, supersedes the earlier rule that a non-finite value was a tokenizer error): a literal whose value overflows (`1e999`) is valid syntax; the token and `NumberNode` hold +infinity with the lexeme kept for §5.5, and evaluating it gives `#NUM!` through `CellValue.FromNumber`. An exponent marker not followed by digits is not consumed (`1e` is Number then Name).
R7 (error literals), restored by R56 (§5.1, §5.5, Phase 3 final review; R56 supersedes R52, which had made matching case-sensitive in Phase 3 Task 1): `#` plus letters/digits/`/`/`!`/`?` must match one of the eight ErrorCodes ignoring ASCII case (internal `ErrorCodes.TryGetCanonical(ReadOnlySpan<char>, out string)`, a FrozenDictionary with `StringComparer.OrdinalIgnoreCase` and a span alternate lookup, allocation-free); the token's Text is the canonical upper-case code, so `=#n/a` evaluates to `#N/A` and prints as `=#N/A`. Anything else starting with `#` (`#FOO!`, `#NULL!`, lone `#`, `#N/AX`, `#n/ax`) is a tokenizer error. The token's Lexeme keeps the text as written. The public `ErrorCodes.IsKnown(string)` stays exact (it validates canonical codes for `CellValue.FromError`). Amended by D-33 (Phase 3 Task 2): the run is greedy except that a known code followed by `/` ends there and the `/` is the divide operator (`#N/A/2` is Error, Slash, Number), so the whitespace-free §5.5 form re-parses; under R56 the backtrack also ignores case (`#n/a/2` is `#N/A`, Slash, Number).
Words: `[$]?[A-Za-z][A-Za-z0-9_.]*` where `$` may also appear inside the word (so `$B$7` is one word). Classification order: any word containing `$` must be a valid in-bounds `CellReference` else tokenizer error (`$foo`, `A$`, `$A$100001`, `AAA$1`; this check runs before the `(` check, so `$A$1(` is a CellRef followed by an LParen, never a Function; the tokenizer accepts it and the parser rejects it as adjacent operands, see D-13); otherwise followed immediately by `(` -> Function (name upper-cased); valid in-bounds reference -> CellRef; TRUE/FALSE case-insensitive -> Boolean; else Name (so `A100001`, `AAA1` are Names). `TRUE(` is a Function; `A1(` is a Function.
Choices: whitespace is space and tab only, skipped between tokens (so `SUM (` is Name, LParen, and `< =` is Less, Equal); `<=`, `>=`, `<>` use longest match; strings use `""` for an embedded quote and an unterminated string is an error at the opening quote; Name tokens keep the case as written; any other character (`@`, `{`, `!`, a lone `.`) is an error at its position. Adjacent oddities such as `1.5.3` or `5abc` tokenize without error and are left for the parser to reject.

### D-13 Formula parser and AST (§5.2, §5.3, §5.4)
`Gridline.Core.Parsing.FormulaParser.Parse(formulaText, IFunctionArityProvider?)` consumes the D-12 tokens and returns a `ParsedFormula` (`Root`, or `ErrorMessage` + 0-based `ErrorPosition`); user-input errors never throw (only a null text throws ArgumentNullException). A failed parse is stored as a formula evaluating to `#PARSE!` (§5.4). Tokenizer failures, an empty formula (lone `=`) and every syntax error below are parse errors. Parsing depends only on Addressing and root Core types.
AST (§5.3): immutable sealed classes under abstract `FormulaNode`: `NumberNode(Value, Lexeme)`, `StringNode` (unescaped), `BooleanNode`, `ErrorNode` (canonical code), `CellRefNode(CellReference)`, `RangeNode(Start, End)` (both refs and `$` flags kept as written; normalisation is CellRange's job at evaluation), `NameNode` (case as written), `FunctionCallNode(Name upper-cased, Arguments)` (read-only list), `OmittedArgNode` (explicit node, not null, for `IF(A1,,3)`), `UnaryNode(UnaryOperator, Operand)`, `PercentNode`, `BinaryNode(BinaryOperator, Left, Right)`, and `ParenNode` (explicit groups kept for §5.5 printing). Nodes carry no source positions.
Precedence (§5.2), tightest first: `:`; prefix `+`/`-`; postfix `%`; `^`; `*` `/`; `+` `-`; `&`; comparisons. So `-2^2` = `(-2)^2`, `2^3^2` = `(2^3)^2`, `-50%` = `(-50)%`, `50%%` = `(50%)%`, `2^-2` is valid, `1+2&3` = `(1+2)&3`, `"a"&1=1` = `("a"&1)=1`. Choice: every binary level is left-associative, comparisons included (`1=2=3` = `(1=2)=3`). Choice: the parser is iterative (shunting-yard style with explicit operand, operator and group stacks), not recursive descent; a first recursive version overflowed a thread-pool stack at about 880 nested calls, below the R8 cap, because unoptimised JIT frames are large. Call-stack use is now constant (tested on a 256 KB thread at the cap). Note for consumers: R8 bounds parens/calls/unary only, so a left-associative chain such as `1+1+...+1` yields an AST whose left spine can be about 16,000 nodes deep in a 32,767-character formula; the evaluator and printer must not recurse naively on `BinaryNode.Left`.
`:` rule: the primary production is `CellRef [':' CellRef]`; any other use of `:` is a parse error (`A1:5`, `(A1):B2`, `A1:B2:C3`, `x:y`, `A1:`, `:A1`, `A1:(B2)`, `SUM(A1):B2`, `1:2`).
Calls: `Function '(' [arg {',' arg}] ')'` where an empty arg is `OmittedArgNode`; omitted args count toward arity: `F()` has 0 args, `F(,)` 2, `F(1,)` 2, `IF(A1,,3)` 3.
R3 (arity): `IFunctionArityProvider.TryGetArity(upperName, out min, out max)` lives in Parsing; a known name whose argument count is outside [min, max] is a parse error positioned at the function token; unknown names parse; a null provider skips arity checks. The root-namespace `FunctionArityAdapter` connects it to the Functions table (D-18).
Adjacency (choice, carried from the D-12 review): after a complete expression anything but End is a parse error, so adjacent operands are rejected: `5abc` (Number, Name), `5A1` (Number, CellRef), `1.5.3` (Number, Number), `A1 B2`, `(1)(2)`, `$A$1(1)` (CellRef, LParen). A Name followed by `(` (`SUM (1)`, i.e. a space before the paren) is a parse error at the `(`. Unbalanced parentheses, a comma outside a call (`1,2`, `(1,2)`) and a missing operand (`1+`, `*1`, `()`) are parse errors.
R8 (depth cap): parentheses, function calls and each prefix unary operator each add one nesting level, counted together and restored on exit (siblings do not accumulate); a level beyond `FormulaParser.MaxNestingDepth = 1024` is a parse error positioned at the token that opened it. 1024 levels parse; 1025 and 2000 nested parens, and 32,767 `(` or `-` characters, are parse errors without stack overflow.
R13 (call cap, §5.4, §6.7): function calls also nest at most `FormulaParser.MaxCallNestingDepth = 64` deep, counted only over calls (parentheses and unary operators do not count; sibling calls do not accumulate). The 65th nested call is a parse error positioned at its function token, so the formula evaluates to `#PARSE!`. The combined 1024 cap still applies, so 64 calls each wrapped in 15 parentheses parse, but no formula nests calls deeper than 64. Reason: evaluating a call re-enters the evaluator through lazy arguments, and real functions cost about 700 B of stack per level, so 1024 levels would leave too little headroom on a 1 MB thread.

### D-14 Evaluator entry point and function-call interface (§6.1, §6.6, §6.8, §7.0)
`Gridline.Core.Evaluation.FormulaEvaluator.Evaluate(ParsedFormula, ICellValueProvider, IFunctionResolver? = null)` returns a `CellValue`. It depends only on Parsing, Addressing and root Core types (never Dependencies or Commands, §3.3). A failed parse gives `#PARSE!` (§5.4). Every `NameNode` and every function the resolver does not know gives `#NAME?` (names arrive in Phase 4); a null resolver means no functions. A Blank final result (`=A1` with A1 empty, or a function returning Blank) becomes the number 0 (§6.6); inside an expression a blank reference stays Blank so it can adapt (`=A1&"x"` is `x`, `=A1=""` is TRUE). Exceptions only come from null arguments or from a provider or function that throws.
Interface (function-facing types never expose Parsing, so Functions can avoid that namespace): `ICellValueProvider.GetValue(CellAddress)` returns Blank exactly for a truly empty cell (formula results are never Blank, so text `""` is not blank). `IFormulaFunction.Invoke(IFunctionArguments)` returns a value; `IFunctionResolver.TryResolve(upperName, out IFormulaFunction?)`. `IFunctionArguments` has `Count` (omitted included), `IsOmitted(i)`, `IsReference(i)` (a `CellRef` or range, through any parentheses, R12), `Evaluate(i)` (lazy, re-evaluated on each call; range gives `#VALUE!` per §6.5/R11; empty cell gives Blank; an omitted argument gives `#VALUE!` (§5.3, R38, Phase 3 Task 1), so a function with a default for that position checks `IsOmitted(i)` first; errors are values) and `EnumerateReferenceValues(i)` (throws InvalidOperationException for a direct argument). It is valid only during `Invoke` (afterwards InvalidOperationException); a bad index throws ArgumentOutOfRangeException.
Choice: argument errors are not propagated automatically; each function decides, so IFERROR/ISERROR can see them. The evaluator turns a function's text result longer than 32,767 into `#VALUE!` (§6.3).
P-4 (§12): `EnumerateReferenceValues` returns `ReferenceValues`, a struct over (provider, normalised `CellRange`) with a struct enumerator yielding `ReferenceValue(Address, Value)` plus `IsBlank`, row-major (top row first, left to right). A SUM over 100,000 cells allocates nothing per cell (test: under 16 KB in total). Function tests can build a `ReferenceValues` directly over any provider.

### D-15 Evaluation without deep recursion (R9, R8, R13, §6.7)
The evaluator walks the AST with an explicit work stack and value stack. Binary, unary, percent and paren chains never recurse; a 16,000-operator `1+1+...` chain evaluates on a 1 MB thread. The only re-entry is a function evaluating a lazy argument (`IFunctionArguments.Evaluate`), which R13 bounds at 64 nested calls. Nested evaluations share the stacks: each works above the heights it found and restores them in a `finally`, and popped slots are cleared. Backstop (R13b): before re-entering, `Evaluate` calls `RuntimeHelpers.TryEnsureSufficientExecutionStack()` and returns `#NUM!` rather than recursing when the stack is nearly exhausted, so a stack overflow, which cannot be caught and would crash on every load, becomes an error value. No `AggressiveOptimization` attributes: with the 64 cap they are not needed. Tested: 64 nested SUM-like and IF-like ordinary fake functions, including 64 calls x 16 levels = 1024 combined depth, evaluate on a 1 MB thread. In a manual check the same test also passed on 256 KB; on 128 KB the backstop returned `#NUM!` instead of crashing. A fake that uses up the stack before evaluating its argument gets `#NUM!`.

### D-16 Coercions (§6.2)
`Coercion` (public static, for operators and functions). `TryToNumber`/`ToNumber`: a number stays as it is; TRUE/FALSE become 1/0; Blank becomes 0; text is trimmed of U+0020 only (not tab or NBSP) and then matched by `NumberGrammar.TryParse` (§4.3, so `"50%"` is 0.5 and `"1e3"` is 1000); anything else is `#VALUE!`; an error passes through.
`NumberToText` (R14): exactly `ToString("G15", InvariantCulture)`, e.g. `1E-05`, `1.25E-07`, `1E+15`, `1.5E+300`; the only adjustment is that -0 prints `0`. G15 decides when to switch to exponent form (below 1E-4, or 16 or more integer digits). `ToText`: TRUE/FALSE become `"TRUE"`/`"FALSE"`; Blank becomes `""`.
Choice: `ToBoolean` turns a non-zero number into TRUE and Blank into FALSE. Text is TRUE when it is exactly `TRUE` and FALSE when it is exactly `FALSE`, case-insensitive with no trimming. Other text, numeric text included, is `#VALUE!`.

### D-17 Operators and error order (§6.3, §6.4, §6.5)
Arithmetic `+ - * / ^`, unary `-` and postfix `%` coerce operands with `TryToNumber`. R15: unary `+` is a no-op that returns its operand unchanged (`=+"x"` is text `x`, `=+TRUE` is TRUE, `=+"1"=1` is FALSE, errors pass through); a blank operand yields 0 (§6.6), so `=(+A1)&"x"` is `0x`. Every numeric result goes through `CellValue.FromNumber`, so a non-finite result is `#NUM!` and -0 becomes 0. Division by zero (`0/0` included) is `#DIV/0!`. Power: `0^0` is `#NUM!`; `0^negative` is `#DIV/0!`; a negative base with a non-integer exponent is `#NUM!`; overflow is `#NUM!`. Choice: numbers compare exactly (IEEE `==`, no 15-digit rounding).
`&` converts both sides with §6.2 text coercion; a result longer than 32,767 is `#VALUE!` (checked before allocating).
Comparisons never coerce and return booleans (`ValueComparer.Compare`, public). Blank adapts to the other side's type (0, `""` or FALSE), and two blanks are equal. Mixed types order Number < Text < Boolean, so `"1"=1` is FALSE and `"zzz"<TRUE` is TRUE. Text compares with `string.CompareOrdinal` after `ToUpperInvariant`; this is not full case folding, so `"straße"="STRASSE"` is FALSE. FALSE < TRUE.
§6.4: operands are evaluated left then right, and the first error wins. The left operand's own error, or its coercion failure, beats anything on the right: `#N/A+#DIV/0!` is `#N/A`, and `"a"+#N/A` is `#VALUE!`.
§6.5/R11: a range in scalar context is `#VALUE!` even when 1x1 or inside parentheses (`=A1:A1`, `=(A1:B2)`, `=A1:B2+1`). Only `EnumerateReferenceValues` reads ranges.

### D-18 Built-in function table and arity registration (R3, R16, §6.8, §7)
`Gridline.Core.Functions.BuiltInFunctionTable` is an immutable table (name, min/max arguments, `IFormulaFunction`) that implements `IFunctionResolver`; `BuiltInFunctionTable.Default` is built once. Functions never references Parsing: arity is exposed as Functions-owned `FunctionDefinition` / `TryGetArity`, and the root-namespace `Gridline.Core.FunctionArityAdapter` implements `Parsing.IFunctionArityProvider` over it. Registration pattern: one `internal static void Register(BuiltInFunctionTable.Builder)` per family in its own file, called once from `BuiltInFunctionTable.Create()`. The builder rejects duplicates, non-upper-case names and bad arity. No public mutable static state. Variadic maximum is 255 (`MaxVariadicArguments`), so a 256th argument is `#PARSE!` (§5.4). Wrong arity (`=ABS(1,2)`) is `#PARSE!`; an unknown name is `#NAME?`. Choice: COUNTBLANK takes exactly one argument (Excel).

### D-19 Aggregation rules and math functions (§7.0, §7.1, R17)
SUM, AVERAGE, MIN, MAX, PRODUCT, SUMSQ: a reference argument adds only its numbers (text, booleans, blanks ignored; an error cell propagates); a direct argument goes through `Coercion.TryToNumber` (boolean 1/0, numeric text parsed, otherwise `#VALUE!`; errors propagate). An omitted argument is `#VALUE!` in its place in argument order (§5.3, R38; `SUM(1,,2)` is `#VALUE!`). The first error in argument order wins. AVERAGE with no numbers is `#DIV/0!`; MIN/MAX/PRODUCT with no numbers are 0 (R17); SUM and SUMSQ give 0. Overflow gives `#NUM!`. Performance: the reference loop uses the struct enumerator and a struct accumulator (a 100,000-cell SUM allocates under 16 KB in total, tested).
COUNT: references count numbers; direct arguments count numbers, booleans and numeric text; errors are neither counted nor propagated. COUNTA: every non-blank cell including errors and `""`; a direct argument counts unless it is Blank. Both ignore an omitted argument (§7.1 "never errors", R38: `COUNT(1,,2)` = `COUNTA(1,,2)` = 2; this supersedes R34 and the earlier D-31 rule). COUNTBLANK: reference only (else `#VALUE!`); counts blank cells and `""` text.
SUMPRODUCT: reference arguments must have identical width and height, else `#VALUE!` (same cell count but different shape also fails); a direct argument is a 1x1 array; non-numeric entries are 0; errors propagate (dimension check first; then the first error in argument order, each argument scanned fully before the next; superseded by D-31, R35).
ABS, SIGN, INT (floor, so INT(-2.5) is -3), SQRT (negative is `#NUM!`), MOD, POWER, PI coerce like direct aggregation arguments. MOD(n,d) takes the sign of d, `MOD(n,0)` is `#DIV/0!`, and |n/d| >= 2^27 is `#NUM!` (D-31, R35); it uses exact `%` then adjusts, not `n-d*floor(n/d)`. POWER follows the `^` operator rules (0^0 `#NUM!`, 0^negative `#DIV/0!`, negative base with fractional exponent `#NUM!`).

### D-20 ROUND family and integer truncation (§7.1, §6.9)
§6.9: integer-valued parameters truncate toward zero. The only such parameter in the math library is the ROUND/ROUNDUP/ROUNDDOWN digits count (2.9 becomes 2, -2.9 becomes -2, text/boolean coerced first); INT is floor, not truncation, and no other math function takes an integer. Rounding is on the shortest round-trip decimal: the double is formatted with `ToString("R", InvariantCulture)` (at most 17 significant digits), split into an integer mantissa and a power of ten, and rounded with `long` arithmetic, so `ROUND(2.675,2)` is 2.68 and `ROUND(0.285,2)` is 0.29. ROUND is half away from zero, ROUNDUP moves away from zero for any discarded non-zero digit, ROUNDDOWN truncates. Negative digits round to tens, hundreds and so on (`ROUND(1250,-2)` is 1300). Choice: no `decimal` is used, so there is no range limit: a value already coarser than the unit is returned unchanged; a value far below the unit becomes 0 (ROUNDUP gives one unit); the result is rebuilt by parsing "mantissa E exponent" (correctly rounded), and a result beyond double range is `#NUM!`. Digit counts are clamped to +/-1000 before use (no double can be affected beyond that).

### D-21 Logic and information functions (§7.2, R16, R18)
`LogicFunctions` registers IF, AND, OR, XOR, NOT, IFERROR, IFNA, ISBLANK, ISNUMBER, ISTEXT, ISLOGICAL, ISERROR, ISNA. IF takes 2 to 3 arguments, evaluates the condition and then only the chosen branch (a branch that is not taken may hold `1/0` or an unknown function and never runs). The condition uses `Coercion.ToBoolean`: non-zero number TRUE, `"TRUE"`/`"FALSE"` text, blank FALSE, other text `#VALUE!`, an error propagates. Omitted arguments (§5.3, §7.2, R38, superseding the earlier Excel choice): an omitted branch is absent, so its default applies: true branch 0, false branch FALSE, so `IF(c,t)` and `IF(c,t,)` both give FALSE when c is false. An omitted condition is `#VALUE!` (`IF(,1,2)`).
AND/OR/XOR: reference arguments count booleans and numbers (non-zero TRUE) and ignore text and blanks; direct arguments go through `ToBoolean` (non-boolean text `#VALUE!`; an omitted one is `#VALUE!`, R38, so `AND(TRUE,)` is `#VALUE!`). `IFERROR(,x)` catches the omitted argument's `#VALUE!` and returns x. The first error in argument order propagates. No logical value at all gives `#VALUE!` (R18). XOR is TRUE for an odd number of TRUE values. NOT coerces like the IF condition.
IFERROR catches any error and IFNA only `#N/A`; both evaluate the first argument in scalar context (a range gives `#VALUE!`, which IFERROR catches) and evaluate the alternative only when it is needed.
ISBLANK is TRUE only for a reference to one truly blank cell; a formula result of `""` is Text (the provider must return Text `""`, never Blank) and gives FALSE, as does a non-reference or a multi-cell range. ISNUMBER, ISTEXT, ISLOGICAL, ISERROR and ISNA never return an error; a multi-cell range gives FALSE (R18). Arities: IF 2..3, NOT 1, IFERROR/IFNA 2, IS* 1, AND/OR/XOR 1..255.

### D-22 Text functions (§7.3, R14, R16, R19)
`TextFunctions` registers LEN, LEFT, RIGHT, MID, UPPER, LOWER, PROPER, TRIM, CONCAT, TEXTJOIN, FIND, SEARCH, SUBSTITUTE, REPLACE, REPT, EXACT, VALUE. Positions and lengths are UTF-16 code units (a surrogate pair is 2). Text parameters coerce via `Coercion` (number G15, so `LEN(12.5)` is 4; boolean TRUE/FALSE; blank ""); a multi-cell range in a scalar parameter is `#VALUE!`; integer parameters truncate toward zero (§6.9); errors propagate first in argument order. Any text result over 32,767 units is `#VALUE!`, decided from lengths before the string is built (`REPT("x",1E9)` allocates nothing).
LEFT/RIGHT default n to 1, and an omitted n is absent so it is 1 too (§7.3 `[n=1]`, R38: `LEFT("abc",)` is "a"); n<0 is `#VALUE!`. FIND/SEARCH: an omitted start is 1; SUBSTITUTE: an omitted instance replaces every occurrence (R38). Every other omitted text-function argument (including any CONCAT/TEXTJOIN argument) is `#VALUE!` in argument order. MID start<1 or n<0 is `#VALUE!`, start past the end gives "". PROPER upper-cases a letter (`char.IsLetter`) when the previous character is not a letter and lower-cases other letters (`"o'neil 2nd"` is `O'Neil 2Nd`). TRIM strips leading/trailing U+0020 and collapses inner runs; tabs and other whitespace are untouched. UPPER/LOWER are invariant-culture.
CONCAT and TEXTJOIN read ranges row-major, blank cells as "", an error cell propagates (CONCAT: an error later in argument order still beats a length overflow). TEXTJOIN(delimiter, ignore_empty, text1, ...) needs 3+ arguments; ignore_empty goes through boolean coercion; ignore_empty skips empty strings only.
FIND is ordinal and case-sensitive with no wildcards; SEARCH upper-cases both sides invariantly and supports `*`, `?`, and `~`, which escapes the next character whatever it is (§7.3; Phase 3 Task 1 widened it from `* ? ~` only, so `~a` matches `a`); a trailing lone `~` is literal. Start outside 1..LEN+1 is `#VALUE!`; an empty needle returns the start. SEARCH is a non-recursive, non-regex matcher: the pattern is split on `*` into segments, each segment is located greedily left to right, and failure of the leftmost placement ends the search (any later placement could only fail too), so it is O(n*m) with no exponential case (`SEARCH("*a*a*a*a*b", REPT("a",30000))` is tested under 1 s).
SUBSTITUTE is ordinal and case-sensitive, non-overlapping; empty old text returns the text unchanged; instance<1 is `#VALUE!`; an instance beyond the match count returns the text unchanged. REPLACE start<1 or n<0 is `#VALUE!`, start past the end appends. REPT n<0 is `#VALUE!`. EXACT is ordinal. VALUE is `Coercion.ToNumber` (so `VALUE("5%")` is 0.05, `VALUE("abc")` is `#VALUE!`, a boolean is 1/0). Arities: LEN/UPPER/LOWER/PROPER/TRIM/VALUE 1, LEFT/RIGHT/REPT/EXACT 1..2 or 2, MID 3, FIND/SEARCH 2..3, SUBSTITUTE 3..4, REPLACE 4, CONCAT 1..255, TEXTJOIN 3..255.

### D-23 Dependency graph, iterative recalc and cycles (§6.1, §6.7, R9, R20, R21, R22)
`Gridline.Core.Dependencies` (uses Parsing, Evaluation, Addressing and root types only; never Functions or Commands). `PrecedentExtractor` walks the AST with an explicit stack (R9) and collects every cell reference, range (normalised `CellRange`) and name (upper-cased, R20) in the text, including untaken IF branches; duplicates collapse; a failed parse has none but is still a formula cell. `DependencyGraph` keys cells as packed ints (column << 17 | row): forward map formula -> `FormulaPrecedents`, reverse map cell -> direct dependents, name -> dependents, and a `RangeIndex` for range precedents. `SetFormula(address, ParsedFormula?)` replaces a cell's edges (null = now constant/blank).
Range index (§6.1 "range edits, including blank cells inside a range, trigger dependents"): each distinct range is stored once with its dependent set, in a multi-level grid. A range of width w and height h goes to level (ceil log2 w, ceil log2 h) and is registered in the at most 2x2 tiles of that size it overlaps; a lookup probes one tile per non-empty level (at most 198) and filters by containment. Insert/remove touch at most four buckets (removal by recorded position since Phase 2 Task 3, below); lookup is O(levels + candidates), independent of the total range count (100,000 `=SUM(Ar:Ar+9)` formulas: about 25 candidates and 10 hits per lookup; an unrelated edit costs about 0.4 us).
`Recalculate(changed, IRecalcTarget, IFunctionResolver)`: (1) iterative BFS from the formula cells in `changed` and the dependents of the other changed cells builds the affected subgraph as CSR edges precedent -> dependent; every affected formula is fetched from the target before anything is written (an inconsistent target throws with no writes). (2) Iterative Tarjan (explicit call stack) finds SCCs; an SCC of size > 1 or with a self-edge is a cycle and all members get #CIRC! (R22). (3) SCCs are processed in reverse emission order (topological), each non-cyclic formula evaluated exactly once with `FormulaEvaluator` against the target, so downstream cells see #CIRC! as an ordinary error and IFERROR catches it. The affected set is closed under dependents, so a cycle touching it lies wholly inside it, and breaking a cycle recomputes the former members as dependents of the edited cell. `RecalcResult.EvaluatedFormulaCount` is the affected formula count including #CIRC! cells (R21); `ChangedCells` lists formula cells whose value differs from the value the target held before (so the target must keep a formula cell's old value until `SetComputedValue`); directly edited constants are the caller's to report. `RecalculateAll` does the same over every formula (after a load). Measured (Release, test harness incl. parsing the edit): 100,000-cell chain edit of A1 median ~32 ms, count 99,999 (P-2 budget 250 ms); a 100,000-cell cycle is detected without recursion.
Phase 2 Task 3 hardening (§6.1, §6.7, R9, R20, R21, R22): (1) Range index removal is O(1) amortised. It no longer scans the bucket (`List.IndexOf`, linear: running totals `B_r = SUM($A$1:A_r)` put about 34,000 entries in tile 0 of level (0, 17)). Each entry records its position in each of its at most 2 x 2 buckets (an `[InlineArray(4)]` indexed by the tile's offset from the entry's first tile). Removal swap-removes by that position and updates the moved entry's position for the same tile. Ranges stay reference-counted by their dependent set, so the Workbook rollback, which re-adds the old edges through `SetFormula`, is an ordinary add. Measured (Release, `RecalcScaleGates`): clearing all 100,000 running totals through `SetCell(addr, "")` (last row first, the worst order for a scan) took 2,089 ms before and 65 ms after, against a 2 s budget. (2) `PrecedentExtractor` dedupes names with an ordinal `HashSet<string>` and no longer uses `List.Contains`. It keeps first-appearance order and the upper-cased key (R20). (3) Per-node level probing: each index level keeps the bounding box of its ranges. The box only grows while the level is non-empty, so it stays a superset, and it resets when the level empties. A lookup skips a level after four integer compares when the cell is outside the box, before any dictionary probe. With 55 distinct range shapes (1,100 range formulas in columns B..Q) next to the 100,000-cell chain in column A, the chain edit median was about 107-145 ms with no skip and 73 ms with it, against the P-2 budget of 250 ms. EvaluatedFormulaCount stays 99,999. A level whose box covers the cell still costs one probe, which is the residual cost for shapes that overlap the chain's column. (4) The new cycle tests cover two independent SCCs that share a downstream cell: it is #CIRC! by propagation and is evaluated and counted once (R21). They also cover R22: downstream cells such as IFERROR, ISERROR and COUNT over a cycle range are evaluated and are not marked as members. Before the change, these tests were checked against two mutations of `Run`: marking cells downstream of a cycle as members, and excluding #CIRC! cells from the count.

### D-24 Workbook Phase 1 API (§9.1, §9.2, R4, R5, R23, R24)
Surface (R23, nothing speculative per R4), all in the root namespace `Gridline.Core`: `Workbook` with `const int MaxRows = 100000, MaxColumns = 702, MaxInputLength = 32767, UndoLimit = 100` (MaxRows/MaxColumns alias `GridBounds`, MaxInputLength aliases `CellInputInterpreter.MaxInputLength`, so each limit has one source; UndoLimit is unused until Phase 3); `SetCell(string, string)`, `GetInput(string)` ("" when empty), `GetValue(string)` (`CellValue.Blank` when empty), `GetUsedAddresses()` (canonical, row-major: row then column), `RecalcStats LastRecalc`, `event EventHandler<CellsChangedEventArgs>? CellsChanged`, and `static Workbook FromCells(IEnumerable<KeyValuePair<string,string>>)` (R5). `RecalcStats` is `readonly record struct RecalcStats(int EvaluatedFormulaCount)` (R21 semantics); `CellsChangedEventArgs.Addresses` is canonical, row-major, deduplicated, and declared as `IReadOnlyCollection<string>` exactly as §9.1 lists it (Phase 3 Task 1; it was `IReadOnlyList<string>`).
Validation (§9.2): a null address or input throws `ArgumentNullException`; an address that `CellAddress.TryParse` rejects (ranges, out-of-grid, whitespace, sheet prefixes) or an input over 32,767 UTF-16 units throws `ArgumentException`, before anything is mutated. GetInput/GetValue validate addresses the same way. Choice: `$` markers are accepted and ignored (`$A$1` is A1), matching `CellAddress.Parse`.
SetCell: identical input (ordinal comparison; "" against an empty cell included) is a complete no-op with `LastRecalc` = 0 evaluated and no event (R24). Otherwise the input is interpreted (§4.3); a formula is parsed with `FunctionArityAdapter` over `BuiltInFunctionTable.Default`, and a failed parse is stored as a formula evaluating to `#PARSE!`. "" removes the cell. Graph edges are replaced only when the old or new content is a formula. A replacement formula keeps the cell's previous value until recalc writes the new one (the Task 11 `ChangedCells` contract). Recalc runs with the edited cell as the changed set. CellsChanged carries the edited cell (its input always changed when the call is not a no-op) plus `RecalcResult.ChangedCells`, raised once after recalc; with no subscriber the address list is not built.
Atomicity (§9.2): storage keeps one `Entry` object per non-empty cell (input, parsed formula, current value), keyed by the packed `CellKey`. Before mutating, SetCell holds the edited cell's old entry; while the call runs, the private `IRecalcTarget` logs every (entry, previous value) it overwrites. If anything throws (e.g. a function implementation), the log is replayed in reverse, the old entry is restored and the old formula's edges are re-set, then the exception is rethrown with no event and `LastRecalc` unchanged. The undo log and the one-element changed set are reused fields, so an edit allocates no workbook-sized structures (P-3 measured ~0.4 us median; 100k-chain edit of A1 ~85 ms, count 99,999, through the facade). Choice: CellsChanged is raised after the change is committed, so an exception thrown by a subscriber propagates but does not undo the edit (the edit itself succeeded).
FromCells (R5): enumerates the input once, validating every entry (null, invalid address, oversized input, duplicates compared on the canonical cell, so `a1`/`$A$1` duplicate `A1`, even when one input is "") before any cell is stored or evaluated; then stores non-empty inputs, sets formula edges and runs one `RecalculateAll`. `LastRecalc` holds that full recalc's count. No event is raised during construction.
Blank semantics (§6.6): a formula result of `""` is stored as Text "" (so `ISBLANK` over it is FALSE); only empty cells are Blank. Test seam: an internal constructor and `FromCells` overload take an `IFunctionResolver` (`InternalsVisibleTo Gridline.Core.Tests`), used to inject a throwing function for the rollback tests; parsing still uses the built-in arities, so unknown test function names parse and resolve through the injected resolver.
Phase 2 Task 2 hardening (§9.1, §9.2, R24, R25): `CellsChangedEventArgs` keeps its public constructor `CellsChangedEventArgs(IReadOnlyList<string> addresses)` (null throws `ArgumentNullException`) and `Addresses`, whose value is a `ReadOnlyCollection<string>` (`Array.AsReadOnly`, declared `IReadOnlyCollection<string>` since Phase 3 Task 1): a handler casting to `IList<string>` gets a read-only list whose writes throw `NotSupportedException`. A `string[]` argument is wrapped without copying, any other list is copied once. `GetUsedAddresses()` returns a read-only wrapper too. Row-major ordering sorts a projected key `row << 10 | column` (column <= 702 < 1024, row <= 100,000, fits in int) with the default int comparer, in place over the key buffer, then formats each distinct key once into the final array (no intermediate list). The rollback undo log is retained for reuse while its capacity is <= 1,024 entries (keeps P-3 allocation-free); a larger log from a big recalc (e.g. a 100k-cell edit) is dropped after the call instead of being held for the workbook's lifetime. Added tests for same-value formula replacement, clearing Text "" (`'`), subscriber exception after commit (R25), `$A$1` addressing, and rollback of a replaced range formula.

### D-25 Canonical .gridline writer and strict loader (§8.1-§8.3, R5, R23, R26, R27)
`Gridline.IO` (references Core only; BCL + System.Text.Json) exposes `GridlineSerializer` (static: `byte[] Serialize(Workbook)`, `void Serialize(Workbook, Stream)`, `Workbook Deserialize(ReadOnlySpan<byte>)`, `Workbook Deserialize(Stream)`) and `GridlineFormatException`. An `internal Serialize(Workbook, IReadOnlyList<KeyValuePair<string,string>> names)` overload (visible to Gridline.IO.Tests) holds the non-empty names path for Phase 4; the public surface always writes `"names": {}`. Path-based atomic save/load is `GridlineFile` (D-26).
Writer (§8.1, R26): hand-written, encodes straight to one growing `byte[]` (no per-cell strings, no BOM, LF only, trailing LF): `{`, `  "format": "gridline",`, `  "version": 1,`, `  "names": {},` (non-empty: `    "NAME": "value"` per line, sorted OrdinalIgnoreCase, closed by `  },`), `  "cells": [` then `    ["A1", "input"]` rows from `GetUsedAddresses()` (row-major) joined by `,` and closed by `  ]` (empty: `  "cells": []`), then `}`. Escapes: `\"` `\` `\b` `\f` `\n` `\r` `\t`, other U+0000-U+001F as lowercase `\u00xx`; `/`, U+007F, non-ASCII and astral characters are literal UTF-8; a lone surrogate is lowercase `\udxxx` (R27) so any .NET string round-trips.
Loader (§8.2, R27): `Utf8JsonReader` (no comments, no trailing commas, depth 64, a single root value) after a whole-input `Utf8.IsValid` check (the reader never decodes skipped values, so without it bad bytes in unknown keys would pass). A leading BOM is skipped. Duplicate keys are detected explicitly on decoded names at every object level, including inside ignored unknown values. Strings containing escapes are decoded by our own routine (the BCL `GetString` rejects lone-surrogate escapes). Unknown top-level keys are ignored; any whitespace and key order are accepted. Checks run after a full syntax pass, in this order: version > 1 (or a number beyond Int64) gives a message containing `unsupported version` regardless of anything else, then format, version type/range, names (object; non-empty rejected until names exist), cells (array). R54 (§8.2, Phase 3 Task 1, supersedes the extra rejections from R28): any integral JSON number is an integer, so `1.0`, `1e0` and `10e-1` are version 1 (`1.5` still fails, `2.0` is unsupported); a missing `names` or `cells` key counts as empty; a missing version still fails. Only then are cell entries read: each must be `[string, string]`, the address must be a valid §4.2 address (Phase 3 Task 1: case-insensitive with optional `$` markers, so `a1` and `$A$1` load as A1; it previously had to be canonical), the input must be at most 32,767 units, and an empty input `["A1", ""]` is a blank cell that `FromCells` skips but still counts for duplicates (R54); duplicates and anything else Core objects to surface as `ArgumentException` from the single `Workbook.FromCells` call (R5) and are mapped to `GridlineFormatException`. Every failure throws before a `Workbook` exists, so nothing partial can leak; a successful load has run one full recalculation (undo/dirty state do not exist until Phase 3).
Measured (Release, 100,000 cells, 3.3 MB): save median ~21 ms (P-5 budget 1 s), load median ~120 ms (P-1 budget 1.5 s); the `PerformanceGates` class (see D-30) asserts both in Release builds.

### D-26 Atomic SaveToPath and LoadFromPath (§8.4, §8.2)
`Gridline.IO.GridlineFile` (static): `void SaveToPath(Workbook, string path)` and `Workbook LoadFromPath(string path)`. Failures: `GridlineIOException` (sealed, distinct from `GridlineFormatException`, underlying exception as `InnerException`) for missing file or directory, access denied, path is a directory, and any other IOException/UnauthorizedAccessException/NotSupported/Security failure (CLI exit 2); `GridlineFormatException` for bad content (exit 3); `ArgumentException` (`ArgumentNullException` for null) for a null workbook or null/empty path. An `ArgumentException` raised by the BCL path APIs themselves (bad path characters) is caught and mapped to `GridlineIOException` (`GridlineFile.cs`), so it is exit 2 in the CLI.
Save: serialize first (a serialization failure never touches disk); resolve `Path.GetFullPath` (bare names go to the current directory); reject a path ending in a directory separator (GridlineIOException, before any temp file); create `.gl-<guid>.tmp` (fixed length, independent of the target name, so a 255-char target name still saves) in the target's directory with `FileMode.CreateNew`; write, `Flush(flushToDisk: true)`, close; then `File.Move(tmp, path, overwrite: true)`. The temp file is deleted best-effort in a `finally` on every failure path, for any exception type (Phase 2 Task 4, §8.4). Only I/O-class failures (IOException, UnauthorizedAccessException incl. a read-only target, NotSupported, Security, path ArgumentException) become `GridlineIOException`; any other exception, including one thrown by the test seam, propagates unchanged after cleanup, so the seam does not alter production catch semantics. So the target is always complete-old or complete-new. Test seam: `internal SaveToPath(Workbook, string, Action<string>? beforeReplace)` runs between close and replace and may throw; it is internal (InternalsVisibleTo Gridline.IO.Tests), not public API. Load: `File.ReadAllBytes`, then `GridlineSerializer.Deserialize`. MarkSaved is not called (Phase 3).
StrictLoader narrowing (Task 13 review): only `JsonException` from the reader and `ArgumentException` from the `Workbook.FromCells` call map to `GridlineFormatException`; InvalidOperationException or anything else from Core now propagates instead of being disguised as a format error.

### D-27 CLI eval and set, exit codes, output rules (§10.1, §10.2, R29)
`Gridline.Cli` (assembly `gridline`, references Core and IO only, no App or System.Windows*, no System.CommandLine) is hand-parsed. `Program` calls `CliApp.Run(string[] args, TextReader stdin, Stream stdout, Stream stderr)` with the console's standard streams; tests call it in-process. `CliContext` buffers stdout and writes UTF-8 without BOM, with explicit "\n"; on any failure the buffer is discarded so stdout is empty, and stderr gets exactly one line `error: <message>\n` (CR/LF inside messages collapsed to a space). `ExitCodes` constants: 0 success, 1 usage, 2 `GridlineIOException`, 3 `GridlineFormatException`, 4 a script printed at least one ERR line, 5 invalid address. An uncaught internal exception gives exit 1 with `error: internal error: ...`. Stdout failures are separate: see D-28 and Fix round 1 below (§10.1). `CliException(exitCode, message)`, `CliContext` and `CellArgs` are the plumbing script mode (D-28) reuses; a new command is one more arm in `CliApp.Dispatch`.
`eval <file> <addr>...` prints `ADDR\t<CellValue.ToCanonicalString()>\n` per address in argument order, ADDR canonicalised (`a1` prints `A1`; `$` markers accepted as `CellAddress.TryParse` does). `eval <file> --all` prints every used cell row-major (empty workbook prints nothing). No addresses and no `--all`, `--all` with addresses, unknown option (any other token starting with `-` in eval) are exit 1. Order of checks: usage, then all addresses (exit 5), then file load (2 or 3), then output; so a bad address never produces partial output and is reported even if the file is missing.
`set <file> <addr> <input> [--out <path>]`: file, address and input are positional (the input is verbatim, so `-5` and `--x` are valid inputs, and `""` clears the cell); only a trailing `--out <path>` is an option. Missing/extra args, unknown option, empty or missing `--out` path and an input over 32,767 UTF-16 units are exit 1; invalid address is 5 (both checked before the file is read). The file is loaded, the cell set, and `GridlineFile.SaveToPath` writes atomically to `--out` or in place; with `--out` the source is never written.
Empty file argument: `eval` and `set` reject an empty `<file>` as a usage error (exit 1, "file argument must not be empty"), as `script --file` does, before anything is read.
Fix round 1 (R29, R30): `CliApp.Run` guards the stdout flush and the stderr write in their own try/catch, so a closed pipe or handle never escapes Run: a successful run whose output cannot be written returns 1 (with a best-effort `error: cannot write output: ...`), a failing run keeps its own code, and a broken stderr is ignored. `set` is strictly positional (R30): only `set <file> <addr> <input>` and `set <file> <addr> <input> --out <path>` are valid; the input is verbatim even when it looks like an option, so `set f A1 --out` stores the text `--out`. `set f A1 x --out` is exit 1 "--out requires a path"; `set f A1 x --out p extra` and `set f A1 x y` are exit 1 "too many arguments". `eval` differs: there the address is not positional-verbatim, so any token starting with `-` other than `--all` is an unknown option (exit 1). `CliApp.RunCore` is an internal seam (InternalsVisibleTo Gridline.Cli.Tests) taking an injectable dispatcher, used to test the internal-error path.

### D-28 CLI script mode, Phase 1 commands (§10.3, R31)
`gridline script` and `gridline script --file <path>` are the only forms (anything else exits 1). `--file` loads via `GridlineFile.LoadFromPath` before stdin is touched; failure is exit 2/3 with one `error:` stderr line. Without `--file` the session starts from `new Workbook()`. Stdin is decoded as UTF-8 regardless of the console code page (`CliApp.OpenStdin`: `StreamReader`, UTF-8 without BOM fallback, BOM detection on), so a leading UTF-8 BOM is tolerated and consumed. Code: `ScriptCommand` (arg handling, read loop, exit code) and `ScriptInterpreter` (one line at a time), dispatched from `CliApp.Dispatch`.
Lines: split on LF only (not on a lone CR, unlike `TextReader.ReadLine`), then one trailing CR is stripped (R31). Empty lines, lines of only spaces/tabs, and lines whose first character is '#' are skipped. The command word is everything before the first space, case-insensitive; a line with a leading space has an empty command word and prints `ERR\tnot implemented`. Every word outside SET, SETX, GET, INPUT, DUMP, STATS, SAVE, LOAD prints `ERR\tnot implemented` (R31).
SET: address is the text up to the second space, input is everything after it, verbatim (inner and trailing spaces kept); `SET A1` and `SET A1 ` clear the cell. SETX: same, after unescaping `\ \t \n \r`; any other backslash sequence or a trailing lone backslash is ERR and the cell is unchanged. Input over 32,767 units is ERR (checked after unescaping). GET prints `ADDR\t<canonical>`; INPUT prints `ADDR\t<input escaped>` using the new public `CellValue.EscapeText` (the same routine as the `T:` form: backslash, tab, LF, CR), so there is one escaping implementation; DUMP prints `ADDR\t<canonical>` per used cell row-major (no args); STATS prints `EVALUATED\t<LastRecalc.EvaluatedFormulaCount>` (0 before any edit and after a no-op set). GET/INPUT take exactly one address, DUMP/STATS none; extra or missing args are ERR. SAVE/LOAD take the path as everything after the first space (spaces allowed); SAVE is the atomic `SaveToPath`; LOAD replaces the workbook only on success.
Errors: any failure (invalid address, arg count, I/O or format error, bad escape, oversize) prints a single line `ERR\t<message>` on stdout (CR/LF collapsed) and the script continues; exit code is 4 iff any ERR was printed. Stdout is flushed after every command, so output memory is bounded by one command's output (DUMP). The final flush keeps the Task 15 guard: a closed pipe on a run that would otherwise succeed gives exit 1; a flush failure mid-script (broken pipe) is reported as `error: cannot write output: <message>` (never "internal error") and ends the run with exit 4 only if an ERR line was actually delivered by an earlier successful flush, else exit 1, including when the failing flush carries the first ERR (R31, §10.1, §10.3); `Run` never throws. Phase 2 Task 5 line cap (§10.3, R33, overrides the brief's "MaxInputLength plus prefix"): a script line is limited to `ScriptCommand.MaxLineLength` = 2 x `Workbook.MaxInputLength` + 64 = 65,598 UTF-16 units, not counting one trailing CR (a SETX tab is 2 raw characters, so 20,000 tabs is a valid 40,000-character line; the 64 covers the command word, address and spaces). A longer line is consumed up to its LF without being buffered, prints `ERR	line too long (limit 65598 characters)`, counts as a script ERR (exit 4) and the script continues; a line of exactly the limit (CRLF line: content exactly the limit) is accepted. Pin tests cover: a mid-line lone CR kept in SET input, an unterminated final line executed, empty stdin (exit 0, no output), `SETX` with `\t` storing a backslash and `t`, and a trailing CR at EOF stripped. A process-level test runs `SAVE bare.gridline` and `set ... --out bare2.gridline` in a child process whose WorkingDirectory is a temp directory, covering `SaveToPath` with a bare file name without touching the test host's current directory.

### D-29 Architecture tests (§3.2, §3.3)
`tests/Gridline.Architecture.Tests` encodes every project and namespace rule as one NetArchTest/reflection test, named `S3_2_*` or `S3_3_*` with the § in a comment. Type-level dependencies are checked (`HaveDependencyOnAny`), not using directives, because ImplicitUsings is on globally.
§3.2: Core references no Gridline project or package (csproj `ProjectReference`/`PackageReference` scan, referenced-assembly scan and type dependency scan) and has no dependency on `System.Windows`, `System.IO.File`, `System.IO.Directory`, `System.IO.FileStream` or `System.Console`. NetArchTest 1.3.2 matches these names as whole type names, not string prefixes (verified in Phase 2 Task 7 with discriminating sanity types), so an earlier claim here that prefix matching also banned `FileInfo` and `DirectoryInfo` was wrong. Ruling R37 therefore adds `System.IO.FileInfo`, `System.IO.DirectoryInfo` and `System.IO.FileSystemInfo` to Core's forbidden-type list explicitly (stricter than the four types §3.2 names; `S3_2_Core_DoesNotUseForbiddenIoType` has a row for each). `System.ConsoleColor` is still allowed (§3.2 names only `System.Console`); `ForbiddenTypeRule_ConsoleColorIsNotConsole` pins that exact-name behaviour so a NetArchTest upgrade that changes matching is noticed. IO references only Core and has no dependency on `Gridline.App`, `Gridline.Cli`, `System.Windows`, `System.Console`. Cli references only Core and IO and has no dependency on `Gridline.App` or `System.Windows`. Extra §2 rule: every src assembly references only the BCL and Gridline assemblies. The App rules (App references Core and IO, not Cli; the WPF-aware BCL rule; R42) were added in Phase 3 Task 6, see D-37.
§3.3: Addressing depends on no other Core namespace; Parsing not on Evaluation/Functions/Dependencies/Commands; Evaluation not on Commands/Dependencies; Functions not on Parsing/Dependencies/Commands; Dependencies not on Functions/Commands. A bare `Gridline.Core` prefix would match every sub-namespace, so siblings are listed by bare name (`Gridline.Core.Parsing`; NetArchTest 1.3.2 never matches a namespace given with a trailing dot, so that form would make every rule vacuous) and a test asserts no Core namespace merely starts with a sibling name. Root-namespace decision: types directly in `Gridline.Core` (Workbook, CellValue, ErrorCodes, ...) count as "another Core namespace" for Addressing, so Addressing may not depend on them (listed by full name); the current code satisfies this. For the other four rules the root is not in the forbidden lists and stays unrestricted (Parsing and Evaluation legitimately use CellValue). Since Phase 3 Task 3 `Commands` holds real types (`UndoHistory`, `UndoStep`, `CellEdit`, D-34), so no rule is vacuous: `S3_3_RuleTargetNamespaces_AreNotEmpty` now has a `Commands` row, and the root `Workbook` (allowed, §3.3) is the only Core type that uses Commands.
No public mutable static state in src/ (§3.3): a reflection test over all four src assemblies (`ArchSupport.AllSrc`: Core, IO, Cli and, since Phase 3 Task 6, App) flags public/protected static fields that are neither `const` nor `readonly`; public/protected `static readonly` fields of mutable type (arrays, `StringBuilder`, and `System.Collections*` types other than Immutable/Frozen, `IReadOnly*` interfaces and `ReadOnly*` wrappers such as `ReadOnlyCollection<T>`); static properties with a public/protected setter; get-only static properties whose type is mutable (e.g. `List<T>`, arrays; a getter that builds a fresh list each call is flagged too, so return an immutable or read-only type instead); and public/protected static events. ### D-33 Canonical formula printer and reference rewriting (§5.5, §3.3, §9.4, §9.5, §9.6, §6.7, R9, R10)
`Gridline.Core.Parsing.FormulaPrinter.Print(FormulaNode root, IReferenceRewriter? rewriter = null, INameCasingResolver? names = null)` returns the §5.5 canonical text including the leading `=`. It takes the AST of a successful parse (`ParsedFormula.Root`); a failed parse has no AST and callers keep the input verbatim. Output: no whitespace outside string literals; `NumberNode.Lexeme` exactly (`1.50`, `1e5`, `.5`, `1e999` per R53); strings re-escaped with `""`; `TRUE`/`FALSE`; error codes as stored, which is the canonical upper-case code (R56: `#n/a` prints `#N/A`); function names upper-cased; references via `CellReference.ToString()` (upper-case, each reference and each range corner keeps its own `$`); `ParenNode` prints exactly its parentheses, none added or removed; omitted arguments print empty (`IF(A1,,3)`); unary/postfix operators without spaces. Iterative: one explicit work stack of nodes and literal text, so a 16,000-term `1+1+...` chain prints on a 1 MB thread (§6.7, R9, R10, D-13). Depends only on Addressing and root Core types (§3.3).

### D-34 Undo/redo, ApplyBatch and dirty tracking (§9.1, §9.2, §9.3, §3.3, §8.2, §12, §14, R24, R25)
Surface: the seven §9.1 Phase 2 members `ApplyBatch(IReadOnlyList<KeyValuePair<string,string>>)`, `CanUndo`, `CanRedo`, `Undo()`, `Redo()`, `IsDirty`, `MarkSaved()` (pinned by `PublicApiShapeTests.Workbook_HasThePhase2UndoSurface`). `Workbook` is now `partial`: `Workbook.cs` keeps the Phase 1 surface and storage, `Workbook.Edits.cs` holds the shared mutation path and the Phase 2 members. The stack itself is in `Gridline.Core.Commands` (§3.3; only the root `Workbook` uses Commands).
Step design (choice): `UndoStep` is an immutable, opaque record of one mutating call; today it holds `ImmutableArray<CellEdit> CellEdits`, each `CellEdit(CellAddress, OldInput, NewInput)` with the exact inputs verbatim, each address once. Undo applies every edit's `OldInput`, redo its `NewInput`, through the same `Workbook.Apply` path as a new edit, so CopyPaste (next task) records a step by building a `CellEdit` list and calling the same internal `Perform`. Phase 4 name and structure edits extend `UndoStep` with optional members (a names before/after snapshot and a whole-sheet restructure payload; `CellEdits` may then be empty) and `Workbook` interprets them; `UndoHistory` treats steps as opaque, so neither the history nor dirty tracking changes. No Phase 4 API was added.
Mutation path: SetCell, ApplyBatch, Undo and Redo all go through `Workbook.Apply(edits, forward)`: build entries (pure), then set every cell and its edges, then one `DependencyGraph.Recalculate` with every edited cell in the changed set (a single edit reuses the one-element scratch array for the changed set, so SetCell's own bookkeeping is O(1) (P-3): one `CellEdit` array, the `CellEdit`, the step and one history node, plus, in `Apply`, two one-element `Entry?[]` arrays (the old and new entries) and the new `Entry`, besides the parse and recalc themselves; corrected in the final review, the earlier text omitted the two `Entry?[]` arrays). Atomic (§9.2): on an exception the written values (rollback log, formerly `_undo`, now `_rollback`) and every touched cell entry and edge are restored and the history is not touched (`UndoHistory.PeekUndo`/`PeekRedo` first, `CompleteUndo`/`CompleteRedo` or `Record` only after success). `Finish` then sets `LastRecalc` and raises `CellsChanged` once with the edited cells plus formulas whose value changed, after the history is committed, so a throwing subscriber leaves the edit and history committed (R25). Undo/Redo always raise when they return true, even if every value comes out identical, because the touched inputs changed (controller resolution). Undo/Redo with nothing to do return false and change nothing, not even `LastRecalc`.
ApplyBatch: validates every entry first (null list → `ArgumentNullException`; null key or value, invalid address or range, input over `MaxInputLength` → `ArgumentException` with ParamName `edits`; nothing applied), last edit per canonical address wins (`a1`, `$A$1`, `A1` are one cell), edits equal to the current input are dropped; if none remain (empty batch included) it is a no-op: no step, no event, `LastRecalc` = 0 like a no-op SetCell (R24; choice, §9.2 "most recent mutating call"). A no-op call does not clear the redo stack (it is not a mutation).
History and dirty (choice, controller resolution): each recorded step gets an id from a monotonic counter; the position is the id of the top undo step, or, when the undo stack is empty, the id of the newest step dropped off the bottom (0 initially). `MarkSaved` stores the position; `IsDirty` = position != saved. Ids are never reused, so a saved position that was dropped (UndoLimit = 100; the 101st `Record` drops the oldest, O(1) via a linked list) or that sat in a redo stack cleared by a new mutation can never match again: dirty until the next `MarkSaved`. `MarkSaved` on a clean workbook is harmless. `FromCells` and therefore every IO load (`StrictLoader`, `GridlineFile.LoadFromPath`) produce a clean workbook with empty history (§8.2). `SaveToPath` does not call `MarkSaved`; the caller (GUI/CLI) marks the save. Known limit (§9.3, §12, recorded in the final review): undo memory is bounded only by the number of steps (UndoLimit = 100), not by size; each step keeps its `CellEdit`s with the old and new input strings, so 100 large pastes or batches (for example 100 pastes of 100,000 cells) keep all of those edits and strings alive until they drop off the bottom or the redo stack is cleared. No byte cap was added (the spec sets none).

In-cell editor (choice): a `TextBox` (AutomationId `CellEditor`, not normative) hosted as the `GridControl`'s only visual and logical child and arranged over the active cell from `GridMetrics` (cell rectangle inset 1 px, widened to the text up to the control's right edge). Keys (§11.4): a printable character on the grid starts an edit whose text is that character, replacing the input (caret at the end). Text comes from the TextInput route (TextCompositionManager), so IME results and non-ASCII characters work; text with any control character is ignored, and a chord with exactly one of Ctrl and Alt is ignored (Ctrl+Alt is AltGr and types). F2 edits the existing input with the caret at the end. In the editor Enter commits and moves down and Tab commits and moves right (Shift reverses, as in Excel); Esc cancels; all return focus to the grid. Commits are one `Workbook.SetCell` each, so one undo step (none when the text is unchanged) and CellsChanged refreshes the grid, formula bar and status bar. Moves clamp, so Enter on row 100000 and Tab on column ZZ commit and stay. Without an open edit, Enter/Tab on the grid just move. While the editor has focus its keys stay in it: arrows, Home/End and PageUp/PageDown edit or do nothing and never move the active cell or scroll the ScrollViewer (Excel's "enter mode" arrow commit is not implemented). Delete on the grid (not Ctrl+Delete) clears the selection.
Delete (§11.4, §9.3): `ClearSelection` builds one `ApplyBatch` from `SelectionSummary.UsedCellsIn(workbook, selection)`, the used cells inside the selection in row-major order. That helper is the D-37 SelectionSum strategy factored out (probe the selection when area <= 4096 or area <= used count, else filter `GetUsedAddresses()`), so the work is O(min(area, used)) and a whole-grid selection never creates 70.2 million edits; SelectionSum now sums over the same helper (same order, same result). With no used cells it does nothing: no batch, no undo step, no CellsChanged.
Ending an edit (choice, Excel behaviour): any change of the active cell while editing (`SelectCell`/`MoveActiveCell`, e.g. a click on another cell) commits to the edited cell first. Keyboard focus arriving at the grid itself (a click on a cell or header) commits in place; focus entering the name box commits in place. Focus moving between the in-cell editor and the formula bar, or into a menu, keeps the edit open. New (Adopt) closes an open edit without committing.
Formula bar (§11.4, choice): Enter commits and keeps the active cell (the spec says only "commits"), Esc reverts to the input; both return focus to the grid.
Name box (§11.4): Enter parses the text with surrounding spaces trimmed through `CellAddress.TryParse`, so `$` markers and lower case are accepted and ranges, A0, A01, AAA1 and rows over 100000 are invalid. A valid address commits any open edit, becomes the active cell (SelectionChanged scrolls it into view) and the box shows the canonical address (also when it was already active); focus returns to the grid. An invalid address reverts the box to the active address and selects its text. Esc and leaving the box revert it too.
R49: `UndoCommand`/`RedoCommand` act on `MainViewModel.EditTextHistory` (`ViewModels/IEditTextHistory`) while an edit is open, and on the workbook otherwise; CanExecute follows the same rule and is re-raised on edit start/end, every pending-text change and when the Edit menu opens. `MainWindow` implements the history over the edit box focused last (the in-cell editor or the formula bar). The editor's history is cleared when an edit starts from the grid, and the formula bar's when it gains focus without an open edit and when an edit ends, so Undo never steps back past the start of the current edit into text the binding put there for another cell. A focused TextBox still handles Ctrl+Z/Ctrl+Y itself (D-37); when it has nothing to undo the key reaches the window binding, which during an edit again goes to the box.

### D-45 Conditional aggregation (§7.5, §6.1, §6.7, §7.0, §3.3, D-41, D-44, R10, R38, R66, R68)

Criteria: a number or boolean value means equality; a blank value acts as `""`; text is parsed once into an operator (`<>` `<=` `>=` `=` `<` `>` or none) and an operand: empty, a number per `NumberGrammar` (so `5%`, `1e3`, `+.5` are numbers), `TRUE`/`FALSE` (case-insensitive) or text. Empty operand with `=` or none: blank cells and `""` text; `"<>"` alone matches every cell whose value is not Blank, `""` text included (controller ruling; a Blank is only a cell with no input, §4.4), never an error cell. Other operators with an empty operand (`"<"`, `">="`) are ordinary text comparisons against `""`. Error cells in `range` never match any criterion, `<>` included.

An undefined or deleted name has no target, so that call contributes no rectangle (the name text dependency still re-evaluates it when the name is defined). No recursion is involved (R10); extraction stays on the explicit stack.
Cycles (§6.7): the resized rectangle is an ordinary range edge, so a formula that (directly or through a chain) reads a cell inside its own resized rectangle is #CIRC!, even when that cell is outside the third argument's text (`D1 = SUMIF(A1:A3,"x",B1)` with `B3 = D1+1`). ### D-46 Date functions (§7.6, §6.2, §6.8, §6.9, §5.4, R38, R69)
DATE, YEAR, MONTH, DAY, WEEKDAY, EDATE, EOMONTH, DAYS in `Functions/DateFunctions.cs` (registered after the conditional family); with this task all 70 §7 functions exist, pinned with their arities by `BuiltInFunctionTableTests.Library_IsExactlyTheSeventyFunctionsOfSection7_WithTheirArities`. Arity (parse time): DATE 3, YEAR/MONTH/DAY 1, WEEKDAY 1-2, EDATE 2, EOMONTH 2, DAYS 2.
Calendar (R69): pure `long` arithmetic, no DateTime, culture or time zone (§6.8). From serial 61 (1900-03-01) the serial is the proleptic Gregorian day count plus 25569 (1970-01-01); serials 0-60 are mapped explicitly (0 = "1900-01-00", 1-31 January, 32-59 February 1-28, 60 = 1900-02-29), and `MonthStart` subtracts one from the Gregorian count for months before 1900-03, so February 1900 has 29 days everywhere (DATE(1900,2,29) = 60, DATE(1900,3,0) = 60, DATE(1900,2,30) = 61, EOMONTH(1900-02) = 60). Valid serials are 0..2958465; the independent DateOnly oracle appears only in a test.
Arguments are coerced per §6.2 (numeric text and booleans coerce, blank is 0, date-looking text is #VALUE!), evaluated left to right with the first error winning, then truncated toward zero (§6.9: -0.9 becomes 0) and only then range-checked. An omitted argument is #VALUE! (R38) except WEEKDAY's type, whose default is 1.
DATE: y < 0 or y >= 10000 is #NUM! (checked after truncation); 0..1899 adds 1900 (so y = 1899 means year 3799). Month and day roll over arithmetically with floor semantics: months total = y*12 + (m-1), serial = start of that month + d - 1, so DATE(2024,-1,1) = 2023-11-01, DATE(2024,1,-1) = 2023-12-30, DATE(1900,0,31) = 0. Choice: a month or day outside the int range (|v| > 2147483647 after truncation) is #NUM!, as is any result outside 0..2958465 (so DATE(1900,0,0) is #NUM!, month 0 of 1900 being December 1899 at serial -30).
YEAR/MONTH/DAY: serial outside 0..2958465 (after truncation, so -0.9 is serial 0 and 2958465.9 is valid) is #NUM!. WEEKDAY: spec gives no range for s, so the same 0..2958465 check applies (#NUM!); the type is truncated and 1, 2, 3 are the only valid values; serial 0 follows the formula (type 1 gives 7, Saturday; type 2 gives 6; type 3 gives 5). The serial is checked after both arguments are coerced, so an error in the type wins over a bad serial.
EDATE/EOMONTH (s < 61 is unspecified; chosen): the serial is split exactly as YEAR/MONTH/DAY split it (60 is 1900-02-29, 0 is day 0 of January 1900), months (truncated) are added to the month index, and the day is clamped to the target month length in the same calendar (February 1900 = 29). So EDATE(31,1) = 60, EDATE(60,1) = 89 (1900-03-29), EDATE(60,12) = 425 (1901-02-28), EDATE(0,1) = 31 (day 0 is kept), EOMONTH(1,1) = 60. Results are computed from the target month start, so negative months, year changes and the 1900/2100 non-leap and 2000 leap rules fall out; a result outside 0..2958465 is #NUM! (a target year below 1800 or above 10100 short-circuits to #NUM!, which only keeps the arithmetic small).
DAYS: floor(end) - floor(start) as doubles through `CellValue.FromNumber`; no range check (R69), so DAYS(2958466,-5) = 2958471.

### D-51 Sheet names and qualified references: tokenize, parse, print, rewrite, extract (CR1.1, CR1.2, §5.1-§5.5, §6.1, §3.3, R10, R82)
Sheet names (CR1.1): `Gridline.Core.Addressing.SheetName` (Addressing depends on nothing else, §3.3). `IsValid(string?)`: 1–31 UTF-16 characters (`MaxLength = 31`), none of `: \ / ? * [ ]`, not beginning or ending with `'`; any other character, spaces and non-ASCII included, is allowed. `Validate(name, paramName)` throws ArgumentNullException for null and ArgumentException (with that ParamName) for an invalid name, for Task 2's workbook members (R78). Uniqueness is the workbook's job. `RequiresQuoting(name)` is true when the name has a character outside `[A-Za-z0-9_.]`, starts with a digit, matches `^[A-Za-z]{1,3}[0-9]+$` (checked by hand, not limited to the grid: `ZZZ1`, `A0` are quoted), or is TRUE/FALSE in any casing. `Format(name)` validates and returns the prefix without `!`: bare, or in `'…'` with each `'` doubled (`O'Brien` → `'O''Brien'`); the caller passes the defined casing.
Tokenizer (amends D-12, R82): a qualified reference is one `CellRef` token whose new `Token.Sheet` is the sheet as written (quotes removed, `''` collapsed) and whose Lexeme is the whole `Sheet!A1` text; `Sheet` is null for every other token. Unquoted prefix: at a token start, the maximal `[A-Za-z0-9_.]` run is checked; when `!` follows it, the run must be a valid name that needs no quoting, else a tokenizer error at the `!` (so `2024!A1`, `A1!B2`, `abc123!A1`, `TRUE!A1` fail, and D-12's `A1!` keeps its error position 2; the ErrorPosition of some other unquoted-prefix errors did move, for example `abc!` 3 -> 4, because the error is now reported at the `!`). Runs may start with a digit or `.` here, so every bare-printable name (`.5abc`, `_x`, `a.b`) re-parses. Choice (linearity): the end of a run already found not to be a prefix is remembered, and a token starting inside it is not rescanned, so `1.2.3...` stays linear (`LongNumberRuns_StillTokenizeInLinearTime`). Quoted prefix: `'…'` with `''` for `'`; unterminated is an error at the opening quote; the closing quote must be followed at once by `!`; the content must be a valid CR1.1 name (`''!A1`, `'a[b'!A1` fail); a redundantly quoted name is accepted. After the `!` comes, with no whitespace, a word that must be a valid in-bounds cell reference (`$` allowed, `Data!$A$1`); a name, a function, a space or anything else is a tokenizer error (`Data!Rate`, `Data!SUM(A1)`, `Data! A1`; `Data !A1` fails on the lone `!`). `Data!A1(1)` tokenizes and the parser rejects it as adjacent operands (D-13).
Parser and AST (amends D-13, CR1.2): `CellRefNode(CellReference reference, string? sheet = null)` and `RangeNode(CellReference start, CellReference end, string? sheet = null)` gain `Sheet` (as written; null = unqualified); the constructors reject an invalid name with ArgumentException. `CellRef [':' CellRef]` takes the sheet of the first token; a qualified second corner is a parse error at its position ("A range has a single sheet prefix"), covering `Sheet2!A1:Sheet2!B3` and `A1:Data!B2`. Whitespace around `:` is allowed as before (`Data!B1 : C2`). The parser stays iterative.
Printer (amends D-33, §5.5 as amended by CR1.2): `FormulaPrinter.Print(FormulaNode root, IReferenceRewriter? rewriter = null, INameCasingResolver? names = null, ISheetCasingResolver? sheets = null)`. New `Parsing.ISheetCasingResolver.GetDefinedCasing(string sheet) -> string?`, the counterpart of `INameCasingResolver`: the defined casing of an existing sheet, or null. A qualified reference prints `SheetName.Format(defined ?? written) + "!"` then the reference with its `$` flags (`Data!$A$1`, `'My Sheet'!A1:B3`); it stays qualified even for the formula's own sheet; `='Data'!A1` prints `=Data!A1`; `=data!a1` prints `=Data!A1` with a resolver that knows `Data`. A resolver casing that is not the same sheet, or a rewriter returning an invalid sheet name, throws InvalidOperationException (programming errors, as for names).
Rewriter (amends D-33): `IReferenceRewriter` gains sheet-aware members with default implementations, `(string? Sheet, CellReference Reference)? Rewrite(string? sheet, CellReference reference)` and `(string? Sheet, CellReference Start, CellReference End)? RewriteRange(string? sheet, CellReference start, CellReference end)`. The printer calls only these; the defaults keep the sheet and delegate to the existing `Rewrite(CellReference)` / `RewriteRange(start, end)`, so `ReferenceShifter`, `StructureRewriter` and every existing test rewriter are unchanged and shift qualified references exactly like unqualified ones for now. Task 2 overrides them: replace the sheet (RenameSheet), return null for `#REF!` (DeleteSheet, R85), or act only on references to one sheet (R84). A returned null sheet prints unqualified.
Precedents (§6.1, CR1.2): new public `Dependencies.CellPrecedent(string? Sheet, CellAddress Address)` and `RangePrecedent(string? Sheet, CellRange Range)`; `FormulaPrecedents.CellPrecedents` and `RangePrecedents` list every distinct precedent in first-appearance order with Sheet null when unqualified, else upper-cased (R20 style, so `Data!A1` and `data!A1` are one). `Cells` and `Ranges` keep exactly the unqualified ones, so unqualified behaviour is unchanged. The R68 SUMIF/AVERAGEIF rectangle lies on the sheet of `sum_range` (internal `ReferenceSpec` gained an optional `Sheet`). ### D-54 RenameSheet, DeleteSheet, MoveSheet with formula and name rewriting and undo; P-8 (CR1.3, CR1.9, §5.5, §9.2, §9.3, §12, R39, R59, R77-R81, R85, D-43)

Rewrite (R85, §5.5, P-8): `DependencyGraph.GetSheetNameDependents(name)` (internal) returns the formulas whose text names the sheet, from the `_sheetNameDependents` index of D-52, so only those are visited; no cell text is scanned. - Rename: the sheet object (and so its id, cells and the active sheet, R80) stays; its `Name`/`Prefix` change (`Sheet.SetName`). A rewritten formula whose new precedents are exactly its old ones with the sheet renamed resolves to the same cells before and after, so it keeps its cell and range edges and only moves between the sheet-name index entries (O(1) per formula); a formula that also named the new name as a missing sheet, or that still names the old name afterwards, is re-edged. The inverse call restores the graph (rollback). Forward (do and redo), rewritten trees are built by `Commands.SheetRenamer` (iterative, shares unchanged subtrees) instead of re-parsed; undo parses the verbatim old text. `InsertSheet` is now atomic: it checks the index, adds the id and name lookups and the graph binding (each undone if a later one fails), and inserts into the list last. `RemoveSheet` refuses an unknown sheet or the only sheet before changing anything.
Sheet id 0: nothing in src assumes it exists or comes first (`ToSortedAddresses` uses `_sheets[0].Id`; the loader's `_sheets[0]` is the first loaded sheet). ### D-58 CLI `--sheet`, qualified addresses and the sheet script commands (CR1.7, §10.1-§10.3, §3.2, R31, R40, R72, R73, R77, R78, R80, R82, R83, R87, D-27, D-28, D-36, D-48)
Address arguments (CR1.7, R83, R87): eval, set, GET, INPUT, SET and SETX parse `[<sheet>!]<cell>` with the R82 prefix rules (a quoted prefix with `''`, holding a valid name, followed at once by `!`; an unquoted prefix only when valid and needing no quotes) and a single cell (`CellAddress.TryParse`, case-insensitive). The echo is canonical: the cell as in Phase 1, and, only when the argument was qualified, the sheet in its defined casing through `SheetName.Format` (quoted only when required: `'my sheet'!c3` → `'My Sheet'!C3`, `'Data'!B2` → `Data!B2`, `data!a1` → `Data!A1`); an unqualified argument stays unqualified and means the active sheet. The resolved string is what is passed to the workbook. eval resolves every address (syntax, then the sheet's existence after the load) before printing anything.
Error mapping (§10.1): a malformed address or prefix → exit 5 (unchanged); an unknown sheet in eval or set → exit 5 ("unknown sheet 'X'"; it is an invalid address, chosen by analogy, not ruled), and set writes nothing. In scripts every failure is `ERR	<message>` (R87): CLI-side argument errors have CLI messages; Workbook exceptions (ArgumentException including ArgumentOutOfRangeException and unknown sheets, and InvalidOperationException from the sheet operations and structure edits: last-sheet delete, 256th sheet, a rewrite over MaxInputLength, cells off the grid) give the exception message on one line. InvalidOperationException is converted only around the sheet commands and structure edits; elsewhere it remains an internal error (D-48).
import-csv / export-csv (R72, R87): after the two paths, `--delimiter <c>` and `--sheet <name>` in either order, each at most once; a missing value, a repeated option, an unknown token, an invalid name (CR1.1) → exit 1 before any file is touched. `import-csv --sheet N` writes a file whose only sheet (and active sheet) is N: a new workbook's Sheet1 is renamed to N while empty (no formula rewrite) and the imported inputs are applied verbatim as one batch, so the file equals the plain import's bytes except for the sheet name; without `--sheet` the output is unchanged (Sheet1). `export-csv --sheet N` exports that sheet (case-insensitive); an unknown name → exit 1 after the load and before the output is created; without `--sheet` it exports the active sheet as before.
Script splitter (R31, R87): the command word is still up to the first space. Arguments are separated by single spaces (a double or trailing space still gives an empty token and a usage ERR), except that a token starting with `'` first runs to its closing quote (`''` is a literal quote) and then to the next space, so `'My Sheet'!A1`, `'It''s'` and `NAME x 'My Sheet'!$A$1` are single tokens. SET/SETX take only the address token this way; the input is the rest of the line after the one following space, verbatim (`SET 'My Sheet'!A1 hello  world ` keeps both spaces; `SET 'My Sheet'!A1` clears). An unterminated quote → `ERR	unterminated quoted sheet name`. UNNAME, SAVE and LOAD are unchanged.
Argument grammar per command: `ADDSHEET <name> [index]`, `RENAMESHEET <old> <new>`, `DELETESHEET <name>`, `MOVESHEET <name> <index>`, `ACTIVATE <name>`, `SHEETS` (no arguments), `INSERTROWS|DELETEROWS [<sheet>!]<row> <n>`, `INSERTCOLS|DELETECOLS [<sheet>!]<col> <n>`, `PASTE <srcRange> <dstAddr>` and `NAME <name> <refersTo>` (both tokens quote-aware; the workbook parses them, R83, R77). A sheet-name argument is either quoted (`'…'`, `''` for `'`, nothing after the closing quote; its validity, existence and uniqueness are the workbook's ArgumentException) or bare, in which case it must be a valid CR1.1 name that needs no quoting (`ADDSHEET 2024` → `ERR	sheet name '2024' must be quoted`, as `2024!A1` is #PARSE! under R82). Index, row and count arguments are `^[0-9]+$` and must fit an int (R73, R87); range checks are the workbook's (R78). The sheet prefix of INSERTROWS…DELETECOLS follows R82; an unqualified one acts on the active sheet (R84). SHEETS prints `SHEET	<index>	<name>` for each sheet (0-based, defined casing, unquoted) and then `ACTIVE	<name>`. ACTIVATE makes no undo step and leaves DIRTY unchanged (R80); the other new commands are one undo step each.
BEGIN…END (R40, R87): inside a block every new command, ACTIVATE and SHEETS → `ERR	command not allowed inside BEGIN block`; qualified SET/SETX are validated (including the sheet's existence) when read and batched as before, so they are one ApplyBatch at END.
DUMP and eval --all follow GetUsedAddresses (CR1.3, R81): unqualified with one sheet, else qualified in sheet order then row-major. NAMES prints the qualified values (R77). Output stays UTF-8 without BOM with LF (§10.1).
Sheet names on stdout (controller ruling, security review): CR1.1 allows TAB, LF and CR in a sheet name, so a name loaded from a file could forge output lines or fields. Every stdout data line that prints a sheet name escapes TAB, LF and CR with the §8.3 escapes (`\t`, `\n`, `\r`) through `CellValue.EscapeText` (`CellArgs.Echo`): SHEETS and ACTIVE, the address echo of GET, INPUT and eval, DUMP and eval --all (GetUsedAddresses strings) and the NAMES refersTo values. `EscapeText` also escapes `\`, which a sheet name cannot contain, so a name without control characters prints verbatim and the CR1.7 output is unchanged for it. Only the echo is escaped: `Resolve` still passes the raw qualified string to the workbook. ERR and stderr messages are already made one line by `CliContext.OneLine`.
§3.2, ruling P1 precedent (controller ruling): the CLI reuses Core's internal `SheetName.TrySplitQualified` and the new internal `SheetName.TryReadQuoted` (the quoted-name reader, now also used by `TrySplitQualified` itself) through `<InternalsVisibleTo Include="gridline" />` in Gridline.Core.csproj, so the R82 prefix rules have one implementation. Core's public surface is unchanged by this task (see the D-53 wording on the Gridline.Core namespace and the infrastructure namespaces). The Cli's `CellArgs` and `AddressArg` are internal (the Cli tests see them through the existing InternalsVisibleTo).
