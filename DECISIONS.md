# Gridline decisions

Decision log for Gridline (.NET 10 Windows spreadsheet engine plus CLI). Each entry cites the spec section it implements.

## Phase 1

### D-1 Solution layout (§3.1)
`Gridline.sln` at the root with `src/Gridline.Core`, `src/Gridline.IO`, `src/Gridline.Cli` and `tests/Gridline.{Core,IO,Cli,Architecture}.Tests`. The App project is deferred to a later phase.

### D-2 Project references (§3.2)
Core references nothing. IO references Core. Cli references Core and IO. Each test project references the src projects it tests; Architecture.Tests references all three src projects.

### D-3 Build settings (§2)
Shared settings live in the root `Directory.Build.props`: `net10.0`, `LangVersion latest`, `Nullable enable`, `WarningsAsErrors=Nullable` (only nullable warnings are errors), ImplicitUsings enabled. Cli sets `OutputType Exe`, `AssemblyName gridline`, `RootNamespace Gridline.Cli`.

### D-4 Packages (§2)
No packages in `src/`. Test projects take only what they need from the §2 list, with pinned stable versions: xunit 2.9.3, xunit.runner.visualstudio 3.1.4, Microsoft.NET.Test.Sdk 17.14.1, coverlet.collector 6.0.4; Architecture.Tests also NetArchTest.Rules 1.3.2. FsCheck.Xunit is added when first needed.

### D-5 Core namespace folders (§3.3)
Core has Addressing, Parsing, Evaluation, Functions, Dependencies and Commands folders, each held by a `.gitkeep` until populated.

### D-6 Addressing grammar and bounds (§4.2, §4.3)
`Gridline.Core.Addressing` holds `GridBounds` (public consts MaxColumns 702 = A..ZZ, MaxRows 100000), `ColumnName` (letters<->number), `CellAddress` (validated, canonical uppercase no-$ `ToString`), `CellReference` (keeps `$` flags for formulas) and `CellRange` (normalised top-left:bottom-right, so `B3:A1` becomes `A1:B3`). It depends on no other Core namespace. `TryParse` reports failure; `Parse` throws `ArgumentException`; constructors throw `ArgumentOutOfRangeException` for out-of-bounds values. Parsing is case-insensitive, ASCII only, and rejects any whitespace, null, empty, a lone `$`, `A0`, `AAA1`, rows over 100000.
Choice: a row with a leading zero such as `A01` is rejected (matches Excel and keeps one canonical spelling). `CellAddress.TryParse` and `CellRange.TryParse` accept `$` markers and discard them; use `CellReference` when the flags matter.

### D-7 Value kinds and error codes (§9.1)
`Gridline.Core.ValueKind` = Blank, Number, Text, Boolean, Error. `ErrorCodes` is a static class of public consts: DivZero `#DIV/0!`, NA `#N/A`, Name `#NAME?`, Num `#NUM!`, Ref `#REF!`, Value `#VALUE!`, Circ `#CIRC!`, Parse `#PARSE!`. PROVISIONAL: §9.1's text is not available, so the set and constant names come from controller ruling R2 (Excel set minus `#NULL!`, plus `#CIRC!` and `#PARSE!`). Membership is tested with `ErrorCodes.IsKnown`, backed by a private FrozenSet (no public mutable static state, §3.3).

### D-8 CellValue (§9.1, §8.3)
`CellValue` is a readonly struct; `default` and `CellValue.Blank` are the blank value. `FromNumber` normalises -0 to 0 and turns NaN/infinity into the `#NUM!` error, so equality and hash codes stay consistent. `FromText(null)` throws ArgumentNullException; `FromError` throws ArgumentException for a code not in `ErrorCodes`. Choice: reading a payload accessor (`Number`, `Text`, `Boolean`, `Error`) on the wrong kind throws InvalidOperationException rather than returning a default, so kind bugs fail loudly. Equality compares Kind and payload: text and errors ordinally, numbers with `==`. Text longer than 32,767 code units is the caller's concern, not CellValue's.

### D-9 Canonical value strings (§8.3)
`ToCanonicalString`: Blank `BLANK`; Number `N:` + `ToString("R", InvariantCulture)` (-0 prints `N:0` via normalisation); Text `T:` + text with only backslash, TAB, LF and CR escaped (as `\\`, `\t`, `\n`, `\r`); Boolean `B:TRUE`/`B:FALSE`; Error `E:` + code. `ToString()` returns the same form.

### D-10 Cell input interpretation (§4.3)
`CellInputInterpreter.Interpret` (root namespace `Gridline.Core`, no Parsing/Evaluation dependency) applies the rules in order, first match wins: empty -> Blank; leading `=` -> Formula (`FormulaText` is the rest; a lone `=` is a Formula with empty text, which the parser later turns into `#PARSE!`); leading `'` -> Text minus that one apostrophe; case-insensitive whole-string TRUE/FALSE -> Boolean (no trimming, so `TRUE ` is text); number grammar -> Number; otherwise verbatim Text (no trimming, so ` 5` is text). Result is `CellInputResult(Kind, Value, FormulaText)`.
Choice: a lone `'` yields Text `""` (not Blank), so the cell stays a text cell. `MaxInputLength = 32767` UTF-16 units lives on `CellInputInterpreter`; longer input throws ArgumentException, null throws ArgumentNullException.

### D-11 Number grammar (§4.3, §6.2)
`NumberGrammar.TryParse(ReadOnlySpan<char>, out double)` is a hand-written span matcher for `^[+-]?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?%?$`, no allocation or regex. Choice: `\d` means ASCII 0-9 only (non-ASCII digits are text), since the engine is culture-invariant. Value parsed with `double.TryParse(NumberStyles.Float, InvariantCulture)`, trailing `%` divides by 100, -0 normalised to 0, and a non-finite result (`1e999`) is not a number so the input becomes Text. Only one `%` is allowed (`5%%` is text). No trimming here; §6.2 coercion callers trim U+0020 first.

### D-12 Formula tokenizer (§5.1)
`Gridline.Core.Parsing.Tokenizer.Tokenize(formulaText)` (input is the text after the leading `=`) is one linear pass, no recursion, no Regex. It returns a `TokenizeResult` (tokens ending in `End`, or `ErrorMessage` + 0-based `ErrorPosition`); user-input errors never throw (a failed tokenize becomes a `#PARSE!` formula later). `Token` is a readonly record struct: Kind, Position, Lexeme (exact source text, needed for §5.5), plus payload (Number, Text, Boolean, Reference). Depends only on Addressing and root Core types.
R6 (numbers): literal forms are `digits ['.' digits*] [exponent]` and `'.' digits [exponent]`, exponent `[eE][+-]?digits`; no sign and no `%` (those are Minus/Plus and Percent tokens). Value is `double.Parse(lexeme, NumberStyles.Float, InvariantCulture)`; a non-finite value (`1e999`) is a tokenizer error, i.e. `#PARSE!`. An exponent marker not followed by digits is not consumed (`1e` is Number then Name).
R7 (error literals): `#` plus letters/digits/`/`/`!`/`?` is matched case-insensitively against the eight ErrorCodes and normalised to the canonical code (`#n/a` -> `#N/A`); anything else starting with `#` (`#FOO!`, `#NULL!`, lone `#`, `#N/AX`) is a tokenizer error. The token keeps the original lexeme.
Words: `[$]?[A-Za-z][A-Za-z0-9_.]*` where `$` may also appear inside the word (so `$B$7` is one word). Classification order: any word containing `$` must be a valid in-bounds `CellReference` else tokenizer error (`$foo`, `A$`, `$A$100001`, `AAA$1`; this check runs before the `(` check, so `$A$1(` is a CellRef followed by an LParen, never a Function; the tokenizer accepts it and the parser rejects it as adjacent operands, see D-13); otherwise followed immediately by `(` -> Function (name upper-cased); valid in-bounds reference -> CellRef; TRUE/FALSE case-insensitive -> Boolean; else Name (so `A100001`, `AAA1` are Names). `TRUE(` is a Function; `A1(` is a Function.
Choices: whitespace is space and tab only, skipped between tokens (so `SUM (` is Name, LParen, and `< =` is Less, Equal); `<=`, `>=`, `<>` use longest match; strings use `""` for an embedded quote and an unterminated string is an error at the opening quote; Name tokens keep the case as written; any other character (`@`, `{`, `!`, a lone `.`) is an error at its position. Adjacent oddities such as `1.5.3` or `5abc` tokenize without error and are left for the parser to reject.

### D-13 Formula parser and AST (§5.2, §5.3, §5.4)
`Gridline.Core.Parsing.FormulaParser.Parse(formulaText, IFunctionArityProvider?)` consumes the D-12 tokens and returns a `ParsedFormula` (`Root`, or `ErrorMessage` + 0-based `ErrorPosition`); user-input errors never throw (only a null text throws ArgumentNullException). A failed parse is stored as a formula evaluating to `#PARSE!` (§5.4). Tokenizer failures, an empty formula (lone `=`) and every syntax error below are parse errors. Parsing depends only on Addressing and root Core types.
AST (§5.3): immutable sealed classes under abstract `FormulaNode`: `NumberNode(Value, Lexeme)`, `StringNode` (unescaped), `BooleanNode`, `ErrorNode` (canonical code), `CellRefNode(CellReference)`, `RangeNode(Start, End)` (both refs and `$` flags kept as written; normalisation is CellRange's job at evaluation), `NameNode` (case as written), `FunctionCallNode(Name upper-cased, Arguments)` (read-only list), `OmittedArgNode` (explicit node, not null, for `IF(A1,,3)`), `UnaryNode(UnaryOperator, Operand)`, `PercentNode`, `BinaryNode(BinaryOperator, Left, Right)`, and `ParenNode` (explicit groups kept for §5.5 printing). Nodes carry no source positions.
Precedence (§5.2), tightest first: `:`; prefix `+`/`-`; postfix `%`; `^`; `*` `/`; `+` `-`; `&`; comparisons. So `-2^2` = `(-2)^2`, `2^3^2` = `(2^3)^2`, `-50%` = `(-50)%`, `50%%` = `(50%)%`, `2^-2` is valid, `1+2&3` = `(1+2)&3`, `"a"&1=1` = `("a"&1)=1`. Choice: every binary level is left-associative, comparisons included (`1=2=3` = `(1=2)=3`). Choice: the parser is iterative (shunting-yard style with explicit operand, operator and group stacks), not recursive descent; a first recursive version overflowed a thread-pool stack at about 880 nested calls, below the R8 cap, because unoptimised JIT frames are large. Call-stack use is now constant (tested on a 256 KB thread at the cap). Note for consumers: R8 bounds parens/calls/unary only, so a left-associative chain such as `1+1+...+1` yields an AST whose left spine can be about 16,000 nodes deep in a 32,767-character formula; the evaluator and printer must not recurse naively on `BinaryNode.Left`.
`:` rule: the primary production is `CellRef [':' CellRef]`; any other use of `:` is a parse error (`A1:5`, `(A1):B2`, `A1:B2:C3`, `x:y`, `A1:`, `:A1`, `A1:(B2)`, `SUM(A1):B2`, `1:2`).
Calls: `Function '(' [arg {',' arg}] ')'` where an empty arg is `OmittedArgNode`; omitted args count toward arity: `F()` has 0 args, `F(,)` 2, `F(1,)` 2, `IF(A1,,3)` 3.
R3 (arity): `IFunctionArityProvider.TryGetArity(upperName, out min, out max)` lives in Parsing; a known name whose argument count is outside [min, max] is a parse error positioned at the function token; unknown names parse; a null provider skips arity checks. The Functions-to-Parsing adapter arrives with the function library.
Adjacency (choice, carried from the D-12 review): after a complete expression anything but End is a parse error, so adjacent operands are rejected: `5abc` (Number, Name), `5A1` (Number, CellRef), `1.5.3` (Number, Number), `A1 B2`, `(1)(2)`, `$A$1(1)` (CellRef, LParen). A Name followed by `(` (`SUM (1)`, i.e. a space before the paren) is a parse error at the `(`. Unbalanced parentheses, a comma outside a call (`1,2`, `(1,2)`) and a missing operand (`1+`, `*1`, `()`) are parse errors.
R8 (depth cap): parentheses, function calls and each prefix unary operator each add one nesting level, counted together and restored on exit (siblings do not accumulate); a level beyond `FormulaParser.MaxNestingDepth = 1024` is a parse error positioned at the token that opened it. 1024 levels parse; 1025 and 2000 nested parens, and 32,767 `(` or `-` characters, are parse errors without stack overflow.

### D-14 Evaluator entry point and function-call interface (§6.1, §6.6, §6.8, §7.0)
`Gridline.Core.Evaluation.FormulaEvaluator.Evaluate(ParsedFormula, ICellValueProvider, IFunctionResolver? = null)` returns a `CellValue`. It depends only on Parsing, Addressing and root Core types (never Dependencies or Commands, §3.3). A failed parse gives `#PARSE!` (§5.4). Every `NameNode` and every function the resolver does not know gives `#NAME?` (names arrive in Phase 4); a null resolver means no functions. A Blank final result (`=A1` with A1 empty, or a function returning Blank) becomes the number 0 (§6.6); inside an expression a blank reference stays Blank so it can adapt (`=A1&"x"` is `x`, `=A1=""` is TRUE). Exceptions only come from null arguments or from a provider or function that throws.
Interface (function-facing types never expose Parsing, so Functions can avoid that namespace): `ICellValueProvider.GetValue(CellAddress)` returns Blank exactly for a truly empty cell (formula results are never Blank, so text `""` is not blank). `IFormulaFunction.Invoke(IFunctionArguments)` returns a value; `IFunctionResolver.TryResolve(upperName, out IFormulaFunction?)`. `IFunctionArguments` has `Count` (omitted included), `IsOmitted(i)`, `IsReference(i)` (a `CellRef` or range, through any parentheses, R12), `Evaluate(i)` (lazy, re-evaluated on each call; range gives `#VALUE!` per §6.5/R11; empty cell or omitted argument gives Blank; errors are values) and `EnumerateReferenceValues(i)` (throws InvalidOperationException for a direct argument). It is valid only during `Invoke` (afterwards InvalidOperationException); a bad index throws ArgumentOutOfRangeException.
Choice: argument errors are not propagated automatically; each function decides, so IFERROR/ISERROR can see them. The evaluator turns a function's text result longer than 32,767 into `#VALUE!` (§6.3).
P-4 (§12): `EnumerateReferenceValues` returns `ReferenceValues`, a struct over (provider, normalised `CellRange`) with a struct enumerator yielding `ReferenceValue(Address, Value)` plus `IsBlank`, row-major (top row first, left to right). A SUM over 100,000 cells allocates nothing per cell (test: under 16 KB in total). Function tests can build a `ReferenceValues` directly over any provider.

### D-15 Evaluation without deep recursion (R9, R8, §6.7)
The evaluator walks the AST with an explicit work stack and value stack. Binary, unary, percent and paren chains never recurse; a 16,000-operator `1+1+...` chain evaluates on a 1 MB thread. The only re-entry is a function evaluating a lazy argument, which nests at most 1,024 deep (R8). Nested evaluations share the stacks: each works above the heights it found and restores them in a `finally`. Function calls are handled in the loop itself rather than in the per-node `Visit` method, and the three re-entrant methods are marked `AggressiveOptimization`. Unoptimised tier-0 frames overflowed a 1 MB stack at about 880 nested calls. Now 1,000 nested calls pass on 1 MB (the test), and 1,023 passed on 512 KB in a manual check.

### D-16 Coercions (§6.2)
`Coercion` (public static, for operators and functions). `TryToNumber`/`ToNumber`: a number stays as it is; TRUE/FALSE become 1/0; Blank becomes 0; text is trimmed of U+0020 only (not tab or NBSP) and then matched by `NumberGrammar.TryParse` (§4.3, so `"50%"` is 0.5 and `"1e3"` is 1000); anything else is `#VALUE!`; an error passes through.
`NumberToText`: `ToString("G15", InvariantCulture)`; -0 prints `0`. Choice: the exponent keeps its sign but loses leading zeros, so `1E-05` becomes `1E-5` while `1E+15` and `1.5E+300` stay. G15 decides when to switch to exponent form (below 1E-4, or 16 or more integer digits). `ToText`: TRUE/FALSE become `"TRUE"`/`"FALSE"`; Blank becomes `""`.
Choice: `ToBoolean` turns a non-zero number into TRUE and Blank into FALSE. Text is TRUE when it is exactly `TRUE` and FALSE when it is exactly `FALSE`, case-insensitive with no trimming. Other text, numeric text included, is `#VALUE!`.

### D-17 Operators and error order (§6.3, §6.4, §6.5)
Arithmetic `+ - * / ^`, unary `+`/`-` and postfix `%` coerce operands with `TryToNumber`. Choice: unary `+` is numeric too (`=+"4"` is 4, `=+"x"` is `#VALUE!`), not Excel's no-op. Every numeric result goes through `CellValue.FromNumber`, so a non-finite result is `#NUM!` and -0 becomes 0. Division by zero (`0/0` included) is `#DIV/0!`. Power: `0^0` is `#NUM!`; `0^negative` is `#DIV/0!`; a negative base with a non-integer exponent is `#NUM!`; overflow is `#NUM!`. Choice: numbers compare exactly (IEEE `==`, no 15-digit rounding).
`&` converts both sides with §6.2 text coercion; a result longer than 32,767 is `#VALUE!` (checked before allocating).
Comparisons never coerce and return booleans (`ValueComparer.Compare`, public). Blank adapts to the other side's type (0, `""` or FALSE), and two blanks are equal. Mixed types order Number < Text < Boolean, so `"1"=1` is FALSE and `"zzz"<TRUE` is TRUE. Text compares with `string.CompareOrdinal` after `ToUpperInvariant`; this is not full case folding, so `"straße"="STRASSE"` is FALSE. FALSE < TRUE.
§6.4: operands are evaluated left then right, and the first error wins. The left operand's own error, or its coercion failure, beats anything on the right: `#N/A+#DIV/0!` is `#N/A`, and `"a"+#N/A` is `#VALUE!`.
§6.5/R11: a range in scalar context is `#VALUE!` even when 1x1 or inside parentheses (`=A1:A1`, `=(A1:B2)`, `=A1:B2+1`). Only `EnumerateReferenceValues` reads ranges.
